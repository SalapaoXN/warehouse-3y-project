# Silent Sting Data Warehouse

ต้นแบบคลังข้อมูลสำหรับวิเคราะห์แนวโน้มผู้ป่วยจากเหตุสัตว์กัดหรือต่อย เพื่อช่วยทีมสาธารณสุขและผู้วางแผนฉุกเฉินระดับจังหวัดดูจำนวนและรูปแบบเคสตามเวลา พื้นที่ แหล่งสัตว์ และระดับคัดกรอง ไม่ใช่ระบบแนะนำการรักษารายบุคคล

## โครงสร้าง

- **Grain:** 1 แถวใน `fact_bite_triage` ต่อ `patient_id` ที่ไม่ซ้ำใน snapshot ปัจจุบัน
- **มิติ:** วัน, พื้นที่/จังหวัด, แหล่งสัตว์, ตำแหน่งที่ถูกกัด, กลุ่มอาการ และระดับคัดกรอง
- **ข้อมูลสรุป:** จำนวนรายเดือนแยกตามพื้นที่ แหล่งสัตว์ และระดับคัดกรอง
- **ขั้นตอน:** CSV → PostgreSQL → dbt staging และตรวจคุณภาพ → star schema → ตารางรายงาน

## วิธีใช้งาน

เปิด PowerShell ในโฟลเดอร์โปรเจกต์ แล้วสั่ง:

```powershell
python scripts/prepare_seed.py --input "C:\Users\Pongsakorn\Downloads\silent_sting_triage_data_enriched.csv"
docker compose up -d --build postgres dbt airflow
```

เข้า Airflow ที่ [http://localhost:8080](http://localhost:8080) ล็อกอินด้วย user `admin` และรหัสผ่านสุ่มที่สร้างตอนเปิดครั้งแรก ดูรหัสผ่านด้วย `docker compose logs airflow` (ไม่มีรหัสตายตัวใน repo) จากนั้นกดรัน DAG `silent_sting_patient_dw` ด้วยตนเอง DAG จะโหลดข้อมูลและสั่ง `dbt build` ตามลำดับ โดยยังไม่ตั้งเวลารันอัตโนมัติ

ถ้าเตรียมไฟล์ไว้แล้ว ข้ามคำสั่งแรกได้ สั่ง dbt เองด้วย `docker compose exec dbt dbt build` และหยุดบริการด้วย `docker compose down` (ข้อมูลฐานข้อมูลยังอยู่)

## ผลตรวจและข้อควรระวัง

- ตรวจ `dbt build` ผ่าน 92 รายการ; fact มี 1,000,000 แถวและ `patient_id` ไม่ซ้ำใน snapshot ที่ตรวจ
- ถ้า snapshot ใหม่มี `patient_id` ซ้ำ การตรวจคุณภาพจะไม่ผ่าน ต้องทบทวน grain ก่อนใช้งานต่อ
- จำกัดสิทธิ์เข้าถึง `patient_id` เพราะเป็นข้อมูลที่เชื่อมโยงกับบุคคลได้
- ข้อมูลมีวันที่ในอนาคต และไม่มีตัวหารประชากร จึงใช้บอกอัตราความเสี่ยงหรืออุบัติการณ์ไม่ได้
- Airflow ชุดนี้ตั้งไว้สำหรับทดลองในเครื่อง ไม่ใช่ระบบใช้งานจริง
